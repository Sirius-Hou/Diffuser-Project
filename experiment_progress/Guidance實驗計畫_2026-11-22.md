## 0. 要回答的問題

> 原論文說：訓練好的 Diffuser 可以在執行時加一個 guide function，讓計畫「滿足一組限制」，不用重新訓練。這個彈性夠不夠讓它**自己換走廊**（完全堵塞），或至少**在走廊裡閃開**（部分堵塞）？

三層裡的位置：guidance 只動「動作規劃」這一層（Diffuser 的取樣過程）。不用 A*、不用地圖，只用感測到的障礙物矩形。

## 1. 原論文怎麼寫（已讀原文，2205.09991v2）

| 項目 | 原文 |

| 引導公式（Sec. 3.2, Eq. 3） | `p(τ^{i−1} \| τ^i, O) ≈ N(τ^{i−1}; µ + Σg, Σ)`，`g = ∇J(µ)` |
| 推力 α（Algorithm 1, line 8） | `τ^{i−1} ∼ N(µ + αΣ∇J(µ), Σ^i)` |
| J 怎麼來 | "We then train a separate model Jφ to predict the cumulative rewards of trajectory samples τ^i"，也就是在加了雜訊的軌跡上訓練 |
| α 的值（Appendix C） | 大多數任務 α = 0.1，hopper-medium-expert 用 0.0001 |
| Maze2D（Sec. 5.1） | "We plan with Diffuser using the inpainting strategy to condition on a start and goal location"，只用 inpainting，**沒有用 guidance**；"use the sampled trajectory as an open-loop plan" |
| 執行時換任務（Sec. 5.2） | "We use one trained Diffuser for all block-stacking tasks, only modifying the perturbation function h(τ) between settings." |
| 賣點（Fig. 2、Sec. 4、Sec. 7） | "An optional guide function J can be used to bias plans toward those optimizing a test-time objective or satisfying a set of constraints."；"the ability to plan for new rewards without retraining" |

**原版程式（main branch，`diffuser/sampling/functions.py`）和論文的差別**：程式是在算 µ **之前**，把梯度加在目前的雜訊軌跡 x_i 上（`x = x + scale * model_var * grad`，然後才 `p_mean_variance`），不是加在 µ 上。locomotion 設定是 `scale 0.1`、`n_guide_steps 2`、`t_stopgrad 2`、`scale_grad_by_std True`（20 個去雜訊步）。我們用的 maze2d branch 沒有這段程式。

**我們的版本和原論文的差別**：原論文的 J 是另外訓練的網路；我們用手寫的障礙物成本（可微分），不用訓練，所以還是 training-free。報告裡可以寫成「把原論文的 learned guide 換成 analytic cost」。

## 2. 實作

### 2.1 新檔案 `experiments/common/guidance.py`

**成本函數**（在迷宮座標上算，用 torch）：

- 現在的 `obstacles.Obstacle.distance` 在障礙物裡面是 0，**梯度也是 0**，不能直接用。要寫一個 signed distance：
  - 在矩形外：跟現在一樣，`hypot(dx, dy)`。
  - 在矩形內：`−min(x − x_lo, x_hi − x, y − y_lo, y_hi − y)`（負的，越深越負）。
- 每一列的懲罰：`relu(margin − sd)²`，`margin = BALL_RADIUS + guide_margin`（`guide_margin` 預設 0.15）。
- 成本 = 所有列加總。第 0 列和最後一列會被 inpainting 蓋回去，算進去也沒關係。

**引導取樣迴圈**：照 maze2d branch 的 `p_sample_loop` 重寫一份（不改原檔），在每一輪中間插一步。以 x0 版本（建議的主版本）為例：

```
x = randn(B, H, 6); x = apply_conditioning(x, cond, action_dim)
for i = T-1 ... 0:
    t = full(B, i)
    x0 = diffusion.predict_start_from_noise(x, t, model(x, cond, t))   # 不論 predict_epsilon 是哪個，這個函式都回傳 x0
    x0 = x0.clamp(-1, 1)
    if guide_scale > 0 and in_window(i):
        p = unnormalize(x0[..., action_dim:action_dim+2])               # 位置欄，還原成迷宮座標
        p = p.detach().requires_grad_()
        g = autograd.grad(cost(p).sum(), p)[0]                           # 只穿過成本函數，不穿過 U-Net
        p = p - guide_scale * g                                          # 在迷宮座標裡推
        x0[..., action_dim:action_dim+2] = normalize(p).clamp(-1, 1)
    mean, _, logvar = diffusion.q_posterior(x_start=x0, x_t=x, t=t)
    x = mean + (i > 0) * exp(0.5 * logvar) * randn_like(x)
    x = apply_conditioning(x, cond, action_dim)
```

- 位置是第 `action_dim`、`action_dim+1` 欄（maze2d 的 `action_dim = 2`，表格是 [ax, ay, x, y, vx, vy]）。
- `unnormalize`／`normalize` 用 `planner.policy.normalizer` 的 observations 部分（LimitsNormalizer，線性），在 torch 裡寫，只取前兩維。
- 速度欄不動，讓模型下一輪自己對齊。
- `in_window(i)`：`all` = 每一輪；`early` = 只在 i ≥ T/2（前半，雜訊大的時候）；`late` = 只在 i < T/2。

**為什麼用 x0 版本當主版本**：手寫成本只有在「乾淨的軌跡」上才有意義。用 `predict_start_from_noise` 拿到 x0（我們的權重設定是直接預測 x0，請用 `diffusion.predict_epsilon` 確認），在 x0 上算成本、推一下，再用 q_posterior 回到下一輪，不需要額外的網路呼叫。原版程式的 x_t 版本當對照（第 2.3 節）。

### 2.2 接到 planner

- `FrozenDiffuserPlanner.plan(...)` 加可選參數 `guide=None`（一個 dict：`obstacle`、`scale`、`margin`、`window`、`variant`）。
- `guide is None` 或 `scale == 0` 時，**走原本的程式路徑**，一行都不變。
- 有 guide 時，H = 384 也走自己寫的迴圈（Policy.__call__ 沒有地方插）。

### 2.3 對照版本：原版程式的 x_t 版本

- 跟原版 `n_step_guided_p_sample` 一樣：在 `p_mean_variance` 之前，把 `−scale × posterior_variance × ∇cost` 加到 x_t 的位置欄，然後 `apply_conditioning`，再照常取樣。
- 只在 E1 的最佳設定上多跑一組，回答「結論是不是只因為我們選了 x0 版本」。

### 2.4 E0：sanity check（一定要先過）

1. 同一個 seed，`guide_scale = 0`：新迴圈的輸出和原本 `planner.plan` 的輸出一致（`allclose`）。不一致就先找原因，不要往下跑。
2. 用 1 個 probe 情境、`guide_scale = 0.1`：畫出同一個種子有沒有 guidance 的計畫，確認點真的被推離障礙物（方向對、沒有 NaN）。
3. 記錄每 64 條的時間，和診斷 #2 的 `plan_time_s` 比，估計 E1 要跑多久。

## 10. Claude 執行時的修改（11/22 晚上約 19:05 寫，E1／E2 結果出來之前）

Ken 授權：「如果過程發現值得做的實驗直接做沒關係」。以下是跟第 1–8 節不同的地方和原因，都是在看到 E1／E2 結果之前決定的。

**程式**（`experiments/common/guidance.py`、`experiments/blocked/diag/guided_sampling.py`，沒改任何舊檔）
- E0.1 通過：`guide_scale = 0` 時新迴圈和 `planner.plan` 的輸出 **max |diff| = 0**（完全相同，不只是 allclose）。所以 **G0 直接沿用診斷 #2 的 H=384 結果**，不重跑。
- 速度：每 16 條約 20–25 秒（單一程序），和原本一樣；三條平行時每 16 條約 35–60 秒。
- **x0 版的推法改成「多步小步」**：原本一步 `p − α∇cost`，α ≥ 1 時會 overshoot；加上平滑項後一步就發散（平滑項曲率約 8，步長要 < 0.25）。現在是 `ceil(α / 0.1)` 步、每步 ≤ 0.1，總推力 = α（等於梯度流的時間 α）。
- **成本多兩個可選項**（第 2.1 節只有障礙物）：
  - 牆：`relu(0 − sd_牆)²`，只看每點周圍 3×3 格；和逐格暴力計算差 < 1e-6，`>0` 的點和 `point_in_wall` 完全一致。
  - 平滑：`relu(|p[k+1] − p[k]| − 0.15)²`，防止計畫「跳過」障礙物。
  - 原因：只用障礙物時，sweep 顯示計畫被推進牆裡或直接跳過障礙物；不加這兩項，負面結果會被說「成本設計太差」。加了牆就等於用了地圖，報告要寫明。
- **失敗類型的定義修正**：`still_hit` = 有計畫點碰到障礙物；`split` = 沒有點碰到，但兩點之間跨過障礙物（中點碰到）或 max_jump ≥ 0.5；`wall` = 不撞但穿牆 > 5 點。原定義把「跨過去」算成 still_hit。

**α 的範圍**（第 3 節的 0.01–0.3 太小）
- 1 個情境（probe seed 0，多 8 格）×16 條的 sweep：x0 α = 0.1 時計畫還是穿過障礙物（中位數 0 距離）；xt 版 α 到 30 都推不動（推力乘上 posterior variance，很小），100–1000 時 16/16 仍撞到。
- 所以 E1 的組改成：

| 組 | 版本 | α | 成本 |
|---|---|---|---|
| G0 | – | 0 | 沿用診斷 #2 |
| G1 / G2 / G3 | x0 | 0.3 / 1 / 3 | 只有障礙物 |
| G4 | x0 | 1 | 障礙物＋牆（權重 5、margin 0.05）＋平滑 |
| G5 | x0 | 3 | 同 G4（只在有空的 lane 時跑） |
| G6 | xt | 300 | 只有障礙物（原版程式的做法） |

- 砍掉 window（early／late）：時間不夠，且 sweep 裡 α 的影響遠大於這個。
- E2（部分堵塞，8 個情境）：P0（α=0，因為診斷 #2 沒做部分堵塞）、x0 α=1、3，障礙物＋牆＋平滑 α=1、3。

**決定點（取代第 5 節）**
- **A（換走廊）**：多 ≥8 格的 13 個情境裡，某一組有 **≥2 個情境、每個情境 64 條裡至少 4 條「valid 而且經過繞路格」**（對應每次抽 16 條平均 ≥1 條可用）→ 做 E3（完全堵塞，main 的 29 個，exact McNemar 對 B2）。
- **C（短繞路變容易）**：多 ≤6 格的 9 個情境，某一組的 valid 合計 ≥ 2 × G0（G0 = 85/576，所以 ≥ 170/576）→ 也做 E3。因為 main 裡 B2 的失敗有一部分是短繞路（多 ≤6 格 8/18）。
- 選組：先看 A，再看 C；同時通過時，選 13 個長繞路情境裡 valid＋繞路最多的那組。
- **B（部分堵塞）只寫進報告，不觸發 E3**：進度檔已確定空隙 0.5 卡在執行層（±0.12），8 個情境裡 4 個堵同一格。
- A、C 都沒過 → 不做閉環，報告寫負面結果＋圖。

**19:25 補記（看到 G4 第 1 個情境之後改的）**
- G4 原本牆的權重 1、margin 0：第 1 個情境穿牆點中位數 12，比只用障礙物還多。原因是障礙物成本（margin 0.25）把點往牆裡推，牆的成本在牆邊幾乎是 0，兩者在牆裡約 0.3 處平衡。這是成本參數沒調好，不是 guidance 本身。
- 改成牆的權重 5、margin 0.05（lr 0.1 時仍穩定），同一情境 16 條：穿牆中位數 4，仍然 0 條有效。只改了 G4／G5 的牆參數，決定規則不變。

## 11. E2 之後追加：部分堵塞的閉環（探索性，20:20 寫，跑之前）

**為什麼改變第 10 節「B 不觸發 E3」的決定**

**設計**
- 新情境 `partial_fresh`（`configs/partial_fresh.json`）：seed 3000 起、16 個部分堵塞（空隙 0.5），**隨機終點（和 main 一樣，`min_goal_cells` 8）**，其他設定和 `probe_partial` 一樣（`max_triggers` 5、N=16、k=10）。這批情境沒有用來選任何參數。用隨機終點是因為 probe_partial 是固定終點，沒有別的路的 5 個情境裡 4 個堵同一格 (6,8)。

- 次要：分「有別的路／沒有」；撞障礙物比例；規劃時間；失敗在哪一層（採用的計畫本身不撞、但球撞到 = 執行層；沒有不撞的計畫 = 計畫層）。
