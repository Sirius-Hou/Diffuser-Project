## 2. 假說和實驗

**候選解釋**

| 代號 | 說法 |
|---|---|
| 資料頻率 | 模型照訓練資料裡各條走廊出現的比例抽 |
| 直線 | 去噪早期，模型只依起點、終點猜出一條接近 A–G 直線的粗略軌跡；之後被吸到離這條線最近的走廊 |
| 早期決定 | 不管是哪種幾何，走廊在去噪的早期（高噪聲）就定下來，後面只修細節 |

**F1 直線（主要，不用模型）**。每個情境兩條候選路線（格子中心連成的折線）：
- R_b：BFS A → b 接 BFS b → G（經過 b 的最短路）。
- R_d：堵住 b 後的 BFS A → G（繞路）。
- d(R) = 沿 R 的弧長等距取 200 點，到線段 [A 中心, G 中心] 的平均距離（單位：格）。
- Δ = d(R_d) − d(R_b)。Δ < 0 表示繞路比較貼近直線。

**F2 資料頻率（次要）**。E2 的做法（`budget_dataset.py`）擴充到 E1r 的情境。x = 訓練資料裡 A → G 片段避開 b 的比例（n_avoid_b / n_segments）。另外記錄 384 步內的片段數，只做描述。輸出到新的 `results/diag/corridor/e2_all/`，不改已 commit 的 E2。

**F3 去噪軌跡（機制）**。用和 E1/E1r 完全相同的種子重跑 24 個 S 情境（先檢查最後的經過 b 數和已存的 rows 一致），在模型的前向計算上掛 hook，記下 256 步裡每一步模型預測的乾淨軌跡 x̂0（照原本的程式 clamp 到 [−1, 1]，再反正規化）。第 j 步（j = 0 是第一步、噪聲最大；j = 255 是最後一步）：
- v_j：x̂0 有沒有點落在 b 格。
- 定案步數 L：最小的 j，使 j 之後每一步的 v 都等於最後的 v。
- 散布 S_j：同一情境 64 條 x̂0 兩兩之間的平均逐點距離。
- 距離：x̂0 各點到 A–G 線段的平均距離 D_line，到 R_b、R_d 折線的平均最近距離 D_b、D_d。
- 和最後結果的一致率：j ∈ {0, 16, 32, 64, 128} 時 v_j 等於最後 v 的比例。

**F4 從指定路線開始去噪（因果，介入）**。參考軌跡沿 R_d（繞路）或 R_b（經過 b）等速移動，第 359 步到 G、之後停住（同去噪探針的 `reference`），速度 = 位移 / dt，動作 = 0。正規化後在噪聲層級 k − 1 加噪（`q_sample`），從第 k 步開始照原本的 `p_sample` 去噪到 0，每步 `apply_conditioning`。k ∈ {64, 128, 192}（256 步裡剩下的步數，k 越大加的噪聲越多），每個情境、每種路線、每個 k 抽 32 條，用 E1 的方式評分（intact、clear、valid、經過 b）。

## 3. 判讀規則

相關都用 Spearman ρ，p 值用置換檢定（10000 次，固定種子，雙尾）。

**F1 直線**（24 個情境，ρ(Δ, y)）：
- 支持：ρ ≤ −0.5 且 p < 0.05。
- 不支持：ρ > −0.25。
- 其他：不確定。
- 只做描述：|Δ| ≥ 0.2 格的情境裡，「Δ < 0」和「y > 0.5」一致的比例。

**F2 資料頻率**（24 個情境，ρ(x, y)；E1 的一半已經看過，所以另外報告 E1r 的 12 個，只做描述）：
- 支持：ρ ≥ 0.5 且 p < 0.05。
- 不支持：ρ < 0.25。
- 其他：不確定。

**F3 早期決定**（全部 1536 條）：
- 重現檢查：每個情境最後的經過 b 數要和已存的 rows 完全一樣；不一樣就照實報告，改用重跑的結果。
- 早期決定：L 的中位數 ≤ 64（前四分之一）。
- 晚期決定：L 的中位數 ≥ 192。
- 其他：中期。
- 直線前提：第 0 步的 x̂0，在至少 2/3 的情境裡（情境內 64 條取平均）D_line < min(D_b, D_d)。
- 只做描述：S_j 的曲線、一致率。

**F4 介入**（24 個情境合併）：
- 基準：E1/E1r 原本的沒經過 b 比例（合併）。
- 早期形狀決定走廊（支持）：k = 192 時，從繞路開始的計畫沒經過 b 的比例 ≥ 0.5，而且比基準高至少 0.3，同時 intact ≥ 0.5。
- 不支持：k = 64 時，從繞路開始的計畫沒經過 b 的比例比基準高不到 0.2（給了幾乎完成的繞路，模型還是改回最短走廊）。
- 其他：不確定。
- 對照：從 R_b 開始的計畫應該大多經過 b；如果沒有，表示建構方式本身有問題，照實報告。

## 4. 各種結果的意思

| F1 | F3 | F4 | 可以寫 |
|---|---|---|---|
| 支持 | 早期 | 支持 | 走廊在去噪早期由起終點的幾何（接近直線的粗略猜測）決定，不是資料頻率。偏好最短走廊，是因為最短走廊通常最貼近直線 |
| 不支持 | 早期 | 支持 | 走廊在早期就由粗略形狀決定，但不是直線距離；是什麼決定，仍是開放問題 |
| 任一 | 晚期 | 不支持 | 偏好是在去噪後段、細節層級強制出來的 |
| 其他組合 | | | 照實寫，只寫「和……一致」 |

F2 支持的話，資料頻率也是因素之一，和上表並存。

限制：只有 24 個情境、計畫層、起點靜止；R_b、R_d 各取 BFS 的一條，平手的路線沒有列舉；F4 的參考軌跡由手工建構（等速、動作為 0），不完全像訓練資料。

## 6. 追加 F5：起始噪聲是不是決定走廊（2026-11-27，F5 還沒跑；寫的時候 F1、F2 已有結果，F3 只看過 e1_01 一個情境）

- 理由：F3 的煙霧測試（e1_01）中，第 0 步模型預測的軌跡就有 91% 和最後的走廊一致。第 0 步的預測只取決於起始噪聲 x_T 和起終點，所以懷疑走廊主要由 x_T 決定，之後每步加的噪聲影響不大。F3 只看得到相關，F5 直接介入。
- 情境：E1/E1r 原本的 y 在 0.1–0.9 之間（兩種走廊都會出現，否則一致率沒有意義）：e1_02、e1_07、e1_09、e1r_00、e1r_01、e1r_02、e1r_04、e1r_06、e1r_09、e1r_11，共 10 個。
- 做法：每個情境 16 個起始噪聲 x_T，每個 x_T 去噪 8 次，之後每一步的噪聲都不同（共 128 條）；其他和 E1 一樣。腳本：`corridor_trace.py --mode noise`。
- 量：每個情境，p̂ = 128 條裡經過 b 的比例；如果 x_T 無關，同一個 x_T 的兩條計畫結果相同的機率 q = p̂² + (1 − p̂)²；實際觀察到的同 x_T 配對一致率 w。10 個情境取平均得 W、Q。
- 規則：
  - 起始噪聲決定走廊（支持）：W ≥ 0.9 而且 W − Q ≥ 0.15。
  - 不支持：W − Q ≤ 0.05（之後的噪聲和 x_T 一樣重要）。
  - 其他：不確定（兩者都有影響）。
- 只做描述：每個 x_T 的 8 條裡經過 b 的條數。

## 7. 追加 F6：時間對齊的資料頻率（2026-11-27，F6 還沒跑）

- 寫的時候已經看過：F1、F2 的結果（F1 不確定、F2 不支持），F3 的 13 個情境，以及 e1_11、e1_06、e1_03 各 4 條最後計畫的格子序列。
- 發現：時間夠的時候，經過 b 的計畫不是單純走最短路，而是**先走進岔路或死路再折返**，把多出來的時間用掉，最後才走最短路經過 b（例如 e1_06：4 條都先繞進死路 (7,4) 再回頭）。所以真正的競爭是兩種長度差不多的軌跡：「繞一圈的繞路」和「折返＋最短路」。
- 這也表示 F2 量錯了東西：F2 算的是所有 A → G 片段，大多數是很短的直達片段（例如 e1_11 的中位數 53 步），和「用 384 步從 A 到 G」不是同一種軌跡。
- **F6 做法**：和 E2 相同的片段定義（最後一次在 A 到第一次到 G），只保留花了 300–420 步的片段（計畫在第 359 步到 G）。x6 = 這些片段裡避開 b 的比例。片段少於 10 個的情境排除並報告。腳本：`diag/corridor_dataset.py`，輸出 `results/diag/corridor/dataset.json`。
- **規則**（24 個情境減去排除的）：
  - 支持「模型照時間對齊後的資料比例抽」：Spearman ρ(x6, y) ≥ 0.5 且置換 p < 0.05。
  - 不支持：ρ < 0.25。
  - 其他：不確定。
  - 只做描述：x6 和 y 的平均絕對差；時間對齊、經過 b 的片段裡有折返（格子序列出現 c → d → c）的比例。
- **描述（不判讀）**：F3 存下的最後計畫（每個情境 64 條），經過 b 的計畫裡有折返的比例，以及折返到多遠。

## 8. 追加 F7：訓練時真正的條件分布（2026-11-27 04:35，F7 還沒算）

- 寫的時候已經看過：F1–F6 和折返描述的全部結果（F4 支持、F5 不支持、F6 不支持；經過 b 的計畫 1036/1083 有折返）。
- 想法：F2、F6 用的是「片段」（最後一次在 A 到第一次到 G），但模型訓練時看到的是**任意 384 步的視窗**，規劃時固定的是第 0 步和第 383 步。所以最貼近「模型被訓練去重現的東西」的，是：訓練資料裡所有第 0 步在 A、第 383 步在 G 的 384 步視窗（和 `SequenceDataset.indices` 一樣的切法，maze2d 沒有 padding），其中避開 b 的比例。這包含「早到 G 又離開再回來」「中途在別處繞」等片段算不到的軌跡。
- **F7 做法**：x7 = 這些視窗裡，第 0–383 步都沒進 b 的比例（每個視窗權重相同，和訓練損失一樣）。相鄰起點的視窗幾乎重疊，所以另外數「群」：同一條路徑裡連續起點都符合的一段算一群；少於 5 群的情境排除並報告。腳本：`diag/corridor_window.py`，輸出 `results/diag/corridor/window.json`。
- **規則**（24 個情境減去排除的）：
  - 支持「模型照訓練時的條件分布抽」：Spearman ρ(x7, y) ≥ 0.5 且置換 p < 0.05。
  - 不支持：ρ < 0.25。
  - 其他：不確定。
  - 只做描述：x7 和 y 的平均絕對差、平均值；以群為單位的比例。
- 如果不支持：F2、F6、F7 三種資料頻率都對不上，報告寫「模型的走廊比例不是訓練資料在這組端點下的比例」，原因歸到模型本身的歸納偏差（跨情境的平滑），並列為開放問題，不再加實驗。

### 偏離計畫和需要注意的地方

1. **F3 第一次跑有 bug，重跑**：模型每一步預測的乾淨軌跡，第 0 和第 383 點沒有被條件固定（條件是之後才套上去的），第一版把這兩點算進「經過 b」，造成 e1r_00 最後一步的比例 1.00、最後計畫卻是 0.81。發現後停掉、刪掉結果，排除兩個端點後全部重跑；判讀只用重跑的結果。舊結果沒有放進 repo。
2. **F3 的合併數字被極端情境主導**：24 個情境裡 14 個幾乎全部經過或全部不經過 b，這些情境的鎖定步數本來就是 0，第 0 步的一致率也只是反映比例（例如 e1_02 在第 0 步的預測完全沒碰 b，所以一致率 0.45 = y）。只看 y 在 0.1–0.9 的 10 個情境，鎖定步數中位數 0–30、p90 37–69（e1r_09 是 176），判讀仍是「早期」，但「第 0 步就決定」不成立：F5 也顯示 x_T 本身不決定。正確的說法是：**走廊在去噪的前約 30 步（共 256 步）由這段時間加入的隨機噪聲決定**。
3. F1 的「|Δ| ≥ 0.2 時方向一致 18/24」沒有意義：Δ 全部 > 0，而 y ≤ 0.5 的情境剛好 18 個。
4. F6（第 7 節）、F7（第 8 節）是看過前面結果後才加的，各節開頭已寫明當時看過什麼。
5. 事後檢查（不判讀）：同一個情境的 y 很穩定。F5 用新的噪聲重抽 128 條，10 個情境的「沒經過 b」比例和 E1/E1r 幾乎一樣（例如 0.45 對 0.38、0.86 對 0.88、0.19 對 0.18；最大差 e1r_04 0.67 對 0.86）。所以 F2、F6、F7 對不上，不是因為 y 本身雜。
6. F7 的資料比例也不是雜訊：例如 e1_06 有 267 群、x7 = 0.58，模型 y = 0.00；e1r_11 有 60 群、x7 = 0.08，模型 y = 0.78。

**能寫進報告的結論**：在預算內，Diffuser 仍偏好原本的走廊，**不是因為畫不出繞路，也不是因為訓練資料在這組起終點下很少繞路**。走廊在去噪最開始約 30 步隨機決定；每個情境有自己穩定的換走廊機率（24 個情境裡 11 個 ≤ 0.1、10 個在 0.1–0.9、3 個 ≥ 0.9），這個機率和資料頻率無關，和幾何只有不確定的弱關係。

**對系統的意思**：模型會不會換走廊，事前從資料看不出來，只能抽了才知道；而將近一半的情境換走廊機率 ≤ 0.1，多抽樣本也沒用。這支持「需要外部的 A* 決定走廊」（ours），和 guidance、中間 inpainting 都換不了走廊的結果一致。

**還沒回答（開放問題，不再加實驗）**：每個情境的機率到底由什麼決定。F2、F6、F7 排除了資料頻率，剩下的解釋是模型本身的歸納偏差（例如跨情境的平滑：U-Net 是卷積，學到的是局部的移動模式，不是每一組起終點的路線比例），但這一點沒有直接證據。

**限制**：只有 S 組 24 個情境（E1 12 個、E1r 12 個）；起點靜止、只看計畫層；F1–F7 都是探索性的，F6、F7 是看過部分結果後才加的。
